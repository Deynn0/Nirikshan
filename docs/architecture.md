# Nirikshan System Architecture

## Overview
**Nirikshan** is an offline-first, explainable regulatory scrutiny platform designed for institutional document verification under the AICTE Approval Process Handbook (APH).

## Non-Negotiable Architectural Principles

1. **Trust Ladder Hierarchy**
   - Evidence is strictly ranked: `CRYPTOGRAPHIC` > `ISSUER` > `RECORD` > `RULE` > `STRUCTURAL_FORENSIC` > `MODEL`.
   - **Applicant Self-Attestation**: Never counts as verified (`UNVERIFIED_CLAIM`).
   - **Model Inference**: OCR and vision output is **ADVISORY ONLY**. A model finding can never be the sole basis for a PASS or FAIL.

2. **Full Explainability & Citations**
   Every finding generated by Nirikshan strictly carries:
   - `rule_id`: Unique identifier (e.g., `AICTE-2024-LAND-001`)
   - `handbook_citation`: Clause, Page, and Handbook edition
   - `evidence_list`: Itemized evidence records with trust level, source document, extracted value, and validation status
   - `source_bounding_box`: Exact coordinates `[page, x, y, width, height]` pointing to the physical document region where the evidence was located

3. **100% Offline & Air-Gapped Operation**
   - Zero outbound network requests. All verification, cryptographic key validation, and document parsing are performed locally.
   - External API calls are blocked at runtime.

4. **Sandboxed Worker Process for Untrusted Documents**
   - Untrusted PDF and image files are NEVER parsed inside the main API server process.
   - An isolated worker subprocess (`nirikshan.worker.sandbox`) executes document parsing under restricted CPU/memory limits and timeout guards.

5. **Externalized Deterministic Rules**
   - All regulatory formulas and thresholds are defined in versioned YAML/JSON files (`backend/rulesets/`), never hardcoded in application logic.
